ko-en-translator

PyTorch로 트랜스포머를 밑바닥부터 구현해 한영 번역 소형 모델을 만들었습니다. 재현에서 멈추지 않고 가설, 통제 실험, 결론의 순서로 6단계를 밟아, 작은 GPU 한 장으로 논문 단위 번역을 학습하는 데까지 갔습니다.

기간
2026.06 ~ 07
공개
GitHub, Hugging Face (apache-2.0)
환경
로컬 AMD GPU(WSL2 + ROCm)에서 시작해 RTX 4090(24GB)으로 이전
기술
PyTorch, 직접 구현한 BPE 토크나이저, Transformer, minGRU
44.10학술 도메인 BLEU (ko → en)
35.46문서 단위 번역 BLEU (268M)
10.6 vs 16.3GB학습 최대 메모리, minGRU 대 트랜스포머
1.6e-6병렬 스캔과 순차 계산의 최대 오차

OVERVIEW6단계 실험

01직접 구현

구성

한영 공용 BPE 토크나이저(32k, 번역 방향 태그 포함), 인코더-디코더 트랜스포머, 형태소 합성 인코더, minGRU 선형 순환 seq2seq, 학습 루프, 문서 단위 디코딩, 외부 의존성 없는 CPU 서빙 서버까지 직접 작성했습니다.

minGRU

선형 점화식을 로그 공간 병렬 스캔으로 구현해 학습은 병렬로, 추론은 KV 캐시 없이 O(1) 메모리로 돌게 했습니다. 병렬 스캔과 순차 계산의 결과가 최대 오차 1.6e-6으로 같음을 테스트로 보장해, 학습과 추론이 어긋날 여지를 없앴습니다.

02공정한 비교로 구조 바꾸기

설계

"같은 크기, 다른 구조"만 비교하도록 파라미터 수를 60,521,472 대 60,524,544로 맞추고, 같은 데이터, 같은 스텝, 같은 평가로 비교했습니다.

결과

minGRU가 10번의 평가 내내 앞섰고(2만 스텝 val_loss 4.15 대 4.36), 길이 4096 디코딩에서 메모리는 약 2.5배 적고 속도는 2.2배 빨랐습니다.

기각

형태소 합성 인코더 가설은 11번의 평가 모두 열세였고 학습 속도도 1,150에서 225 ex/s로 떨어져 기각했습니다. 원인이 ROCm 라이브러리가 가변 합성곱 배치마다 커널을 다시 탐색하는 데 있다는 것까지 밝혀 기록했습니다.

03문서 단위 번역

설계

문장 구분자로 새 토큰을 만들지 않고 기존 종료 토큰을 재사용해 어휘와 임베딩을 그대로 살렸습니다. minGRU는 위치 임베딩이 없어서 최대 길이를 128에서 1024로 늘려도 파라미터가 같았고, 문장 단위로 학습한 체크포인트를 문서 학습의 출발점으로 그대로 쓸 수 있었습니다.

학습

268M 모델을 OPUS 1,699만 쌍으로 먼저 학습한 뒤, 논문 60,483편에서 만든 179,136개 윈도우로 이어 학습해 val_loss 0.906, 문서 모드 BLEU 35.46.

한계

BLEU 35.46은 짧은 문서 20개 표본의 참고치이고, 긴 문서 디코딩이 O(L²)라 전수 평가는 하지 않았으며 단일 시드입니다.

손실은 좋은데 BLEU가 0.03. 문맥 학습 뒤 val_loss는 2.14로 좋았는데 BLEU가 무너졌습니다. 모델이 아니라 평가 코드를 의심했고, 문장용 디코딩이 첫 종료 토큰에서 멈추는 것을 찾아 입력 문장 수만큼 생성하고 멈추는 디코더를 따로 구현했습니다.

04서빙

외부 의존성 없는 CPU 서버에 일반용과 문서용 두 모델을 함께 올리고, 번역 방향과 입력 길이(토큰 70개 기준)로 모델을 고르게 했습니다. 문서 디코딩이 느린 긴 입력은 문장별로 나눠 타임아웃을 피하고, 같은 서버의 NPU 서비스 호스트 CPU를 굶기지 않도록 스레드를 8개로 제한했습니다.
