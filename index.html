원윈도우 AI 검색 고도화

2026.09 ~ 12 예정 / NIA 사업

검색 백엔드, GPU 추론 서버, 품질 평가 담당

공공데이터 약 13.5만 건을 찾는 국가 서비스의 검색과 챗봇을 LLM 기반으로 바꾸고 있습니다.

환경
폐쇄망 A100 2장
기술
vLLM, EXAONE-4.0-32B-AWQ, k3s, FastAPI, pgvector, MCP
  • 상용 RAG 대체: LLM 검색어 확장, 키워드와 벡터 검색, LLM 재순위로 구성. 100문항 기준 hit@1 71 → 86, 문항당 14.8초 → 1.7초
  • 폐쇄망 추론 서버: 외부 접속이 막힌 서버에 k3s로 vLLM을 구성해 32B 모델과 임베딩 모델을 함께 서빙
  • 운영 문제 규명: 간헐적 500 오류를 keep-alive 경쟁 조건으로 재현해 확정하고, 부하 측정으로 동시 처리 상한 결정

생성 모델 저작권 탐지 연구

2026.08 / 수주 과제

단독 수행

가중치에 접근할 수 없는 상용 이미지 생성 모델의 저작권 침해를, 그 출력으로 학습한 대리 모델에서 탐지할 수 있는지 검증했습니다.

환경
A100 80GB 1장
기술
PyTorch, diffusers, accelerate
  • 풀 파인튜닝: SD1.4와 SD3.5 학습. SD3.5 학습 코드를 직접 작성하고 공용 GPU의 45GB 안에 들어가도록 메모리 설계
  • 결과: 구조가 다른 대리 모델에서도 암기 신호 탐지 AUC 0.848, 통제군 0.522 대비 유의
  • 교란 발견: 0.983이 나온 실험을 그대로 보고하지 않고 통제군으로 교란을 밝힌 뒤 조건을 바꿔 다시 입증

32B 서빙 최적화

2026.07 ~ 08 / 원윈도우 착수 전 사전 실험

A100 한 장에서 32B 모델로 웹 검색 에이전트 채팅 서비스를 만들며 응답 속도와 출력 안정성을 끌어올렸습니다.

환경
A100 80GB 1장
기술
vLLM, EXAONE-4.0-32B-AWQ, 투기 디코딩
  • 생성 속도: 단일 사용자 기준 transformers 약 9 → vLLM AWQ 65 → 투기 디코딩 156 TPS(코드), 81 TPS(일반 문장)
  • vLLM 소스 패치 2건: 투기 디코딩 보조 모델이 매번 느린 경로로 돌던 버그 수정, 이후 업스트림에 같은 수정이 머지됨
  • 출력 안정성: bf16과 AWQ를 비교해 양자화 탓인 환각과 아닌 것을 분리. 사고 태그가 닫히지 않는 문제를 2단계 생성으로 차단

NPU 온프레미스 LLM 추론 서비스

2026.06 ~ 운영 중

단독 수행

벤더가 지원하지 않는 모델을 NPU에 직접 포팅해 상시 서비스로 운영합니다.

환경
Rebellions ATOM-Max NPU
기술
vllm-rbln, optimum-rbln, EXAONE 4.5 VL, bge-m3, PyTorch
  • EXAONE 4.5 33B 포팅: 벤더 패키지가 지원하지 않는 구조를 패키지 수정 없이 구현. 원본 대비 프롬프트 12개 greedy 출력 일치, 76.5 tok/s, 32K 컨텍스트
  • 추론 최적화: 비전 임베딩 캐시로 이미지 10장 대화의 첫 토큰 지연 13.5s → 2.35s. 임베딩 스케줄러 패치로 처리량 3.4배
  • 가속기 검증: 비전 인코더를 추가하며 기존 응답 회귀 0으로 무중단 교체. LSTM이 오류 없이 틀린 값을 내는 NPU 결함을 대조군으로 격리
